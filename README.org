#+title: LispM Desktop

#+HTML: <p align="center"><a href="https://github.com/LispMachineLab/lispm-desktop/actions/workflows/test.yml"><img src="https://github.com/LispMachineLab/lispm-desktop/actions/workflows/test.yml/badge.svg" alt="test" /></a></p>

LispM's Emacs distribution: Emacs laid out as Mac OS 9's desktop and set up as a workspace for
coding agents, ready from the first start.  [[https://github.com/LispMachineLab/lispm-agent][LispM Agent]]'s agents, Claude Code and Codex
share its sidebar, [[https://github.com/LispMachineLab/lispm-browser][LispM Browser]] is its web browser, and its App Store installs more.  In
code, the prefix is ~lispm-desktop-~.

* The LispM projects

| [[https://github.com/LispMachineLab/lispm-agent][lispm-agent]]     | AI agents inside Emacs                                            |
| *lispm-desktop* | Emacs as a Mac OS 9 desktop, set up as a workspace for agents (this repository) |
| [[https://github.com/LispMachineLab/lispm-browser][lispm-browser]]   | a WebKit browser in Emacs, with keyboard hints and Chrome extensions |
| [[https://github.com/LispMachineLab/lispm-store][lispm-store]]     | the catalog LispM Desktop's App Store installs from               |

The agents and the browser each stand on their own; LispM Desktop installs both at its first start.

* Installation

** LispM.app, on macOS

On macOS 11 or later, Apple silicon or Intel:

#+begin_src sh
curl -fsSL https://lispm.ai/install.sh | sh
#+end_src

[[file:install.sh][install.sh]] checks out this repository, lispm-agent and lispm-browser in =~/.lispm=,
and makes =/Applications/LispM.app= from a signed, notarized GNU Emacs of
[[https://github.com/jimeh/emacs-builds][jimeh/emacs-builds]], whose checksum and signature it checks.
A download the connection cuts short goes on from where it stopped, and so does the next
run, should this one give up.  Nothing needs to be known about Emacs to use it.  LispM keeps
itself up to date (see [[*Updating][Updating]]); to uninstall, delete =/Applications/LispM.app= and
=~/.lispm=.

** In your own Emacs

Emacs 30.1 or later (31 recommended) built with SVG images, git and curl, on macOS or GNU/Linux:

#+begin_src sh
git clone https://github.com/LispMachineLab/lispm-desktop ~/lispm-desktop
emacs --init-directory ~/lispm-desktop     # or make it your config: ln -s ~/lispm-desktop ~/.emacs.d
#+end_src

The first start asks for Vim or Emacs keys and an appearance, installs the packages (a few
minutes, once), then tours the desktop.  LispM Agent and LispM Browser are taken from
~load-path~, else from checkouts beside this one (=../lispm-agent=, =../lispm-browser=), else
installed with package-vc.  Give the agents a model with ~OPENAI_API_KEY~ or ~ANTHROPIC_API_KEY~,
or see LispM Agent's [[https://github.com/LispMachineLab/lispm-agent#backends][Backends]].

Optional, used when present:

- ~claude~ and ~codex~ on ~PATH~ (Hermes once the App Store has added it);
- Rust's ~cargo~, only to build the terminal module yourself (see below); by default it is downloaded;
- Swift, on macOS 15.4+, for the browser's Chrome extensions;
- an Emacs built with xwidgets, for the browser;
- the Maple Mono NF CN font, which keeps terminal columns aligned with CJK;
- aspell, hunspell or ispell, for Flyspell.

* What you get

- *Looks and themes*: Mac OS 9's Platinum, Windows 3.2 or OS/2 2.0's Workplace Shell, or the
  glowing Phosphor and Neon, whose windows are glass on macOS; in the Dracula, Platinum,
  Windows 3.2, OS/2, Phosphor or Neon colour theme, or any theme installed.
- *A desktop* with Mac OS 9's icons down its right edge (home disk, Emacs, browser,
  Applications, App Store, Control Panels, Trash), dragged with the mouse or selected with
  =C-n= =C-p= =C-f= =C-b=, over a colour or a picture of your own.
- *A guide* that tours the desktop at the first start, Apple Guide style, with coach marks and
  Show Me (=C-c ?= brings it back).
- *Finder windows*: folders as large icons, with back, forward, up, rename and Move to Trash;
  an item dragged onto the desktop's Trash is thrown away.
- *Applications*, one in front at a time: the desktop, the editor, the browser and whatever the
  App Store installed, each filling the menu bar with its menus beside the rainbow λ.  One
  installed is uninstalled from its right-click menu, in the App Store or the Applications
  folder, or by dragging it onto the Trash; what it alone brought, Homebrew programs and Emacs
  packages, goes too when asked.
- *The editor*, full screen or floating: a sidebar of Files, Agents and Shells, a workspace per
  project (=C-<tab>=, =M-`= for thumbnails), chats and terminals on the left, files on the right.
- *Platinum windows*: title bars with close, zoom and collapse boxes, scroll bars, placards,
  grow boxes, outline moves and resizes, Mac OS 9 menus and alerts, Balloon Help.
- *Agents side by side*: sessions of LispM, Claude Code, Codex and App Store agents (Hermes),
  listed per project.  Claude Code and Codex see the selection, open files and diagnostics;
  programs speaking the [[https://superlogical.com/rex/docs/build/program-status][Program Status Protocol]] show working, done or waiting in their title
  bars (=C-c a n= goes to the next one waiting).
- *Terminals that never stall Emacs*: each emulated on a thread of its own by a Rust module
  built on [[https://github.com/alacritty/alacritty][Alacritty]]'s terminal (=native/lispm-desktop-term=); Emacs redraws only those on
  screen.  The module is downloaded as built for this computer and kept only when its SHA-256 is
  the one this repository pins; Eat stands in until it is there.
- *Control Panels*: Appearance, Desktop, Keyboard, Language, Internet, Network, Sandbox, Startup
  and Software Update, plus a Control Strip along the desktop's edge (=C-c b=, =C-c B=).
- *Seven languages*: English (US and UK), German, French, Japanese, and Chinese, Simplified and
  Traditional; the computer's by default, asked at the first start.
- *The App Store*: applications (Elfeed, EMMS, ERC, Slack, Telega, Calc, games, Classic AI's
  Doctor, MYCIN and SHRDLU, ...) and extensions from [[https://github.com/LispMachineLab/lispm-store][lispm-store]], pinned to reviewed commits,
  installed in the background with the Homebrew programs they need.  Each has a page: its banner,
  its introduction in Markdown, who made it and under what licence.  Their windows get title
  bars, buttons, placards, menus and alerts worked out from their keymaps
  (~lispm-desktop-app-ui-define~ describes the rest).
- *A browser*, in Emacs built with xwidgets: LispM Browser drawn as Netscape Communicator, with
  tabs, history, bookmarks, Vimium-style hints and, on macOS 15.4+, Chrome extensions.
- *Windows out on the screen*, on macOS: a floating window dropped past the desktop's edge joins
  the Mac's own windows, as in Parallels' Coherence; =C-c h= hides the desktop in the Dock.
- *A watch on the pointer* while Emacs is busy, as Mac OS 9 showed it.
- *A modern Emacs underneath*: Vertico, Orderless, Consult, Embark, Corfu, Magit, Eglot,
  tree-sitter; Evil with =SPC= as leader if you chose Vim keys.
- *EXWM*: on an X display with no window manager, Emacs becomes it.

Title bars and menus use Charcoal, else Chicago (or ChicagoFLF), else Geneva.

In the Mac build Command is Meta, so Command-C and Command-V copy and paste everywhere.  With
Vim keys, =SPC= opens the leader and which-key shows what follows.

* Your own settings

Control Panels keep their choices for the next start.  =personal.el=, next to =init.el= and
ignored by git, is loaded after setup and can change anything:

#+begin_src emacs-lisp
(setq lispm-desktop-look 'platinum              ; platinum, win3, os2, phosphor or neon
      lispm-desktop-theme 'platinum             ; dracula, platinum, win3, os2, phosphor, neon or any theme
      lispm-desktop-color "#6666AA"             ; the desktop's colour
      lispm-desktop-picture "~/Pictures/desktop.jpg"
      lispm-desktop-picture-position 'fill)     ; fill, fit, center or tile
#+end_src

To use LispM Desktop as a library in a configuration of your own:

#+begin_src emacs-lisp
(add-to-list 'load-path "~/lispm-desktop/lisp")
(setq lispm-desktop-editing-style 'vim)         ; or 'emacs; nil asks
(require 'lispm-desktop)
(lispm-desktop-setup)
#+end_src

** Languages

The Language panel chooses the language LispM speaks, at once: menus, windows, panels, alerts
and the Guide.  By default it is the computer's: the first of macOS's preferred languages LispM
speaks, or of =LANGUAGE=, =LC_ALL=, =LC_MESSAGES= and =LANG=; else American English.

#+begin_src emacs-lisp
(setopt lispm-desktop-language 'ja)   ; en-US, en-GB, de, fr, ja, zh-Hans, zh-Hant; nil: the computer's
#+end_src

The code writes its words in English through ~lispm-desktop-tr~ and its kin (see
=lisp/lispm-desktop-i18n.el=); =i18n/= holds a catalog per language.

** A proxy

The Network panel sends every connection through one HTTP or SOCKS5 proxy: url.el's, the
programs Emacs starts (through =http_proxy= and friends) and the browser's pages.  Local
addresses and ~lispm-desktop-proxy-exceptions~ connect directly.

#+begin_src emacs-lisp
(setq lispm-desktop-proxy-type 'socks5          ; or 'http; nil for none
      lispm-desktop-proxy-server "127.0.0.1:7890")
#+end_src

** The sandbox

The Sandbox panel sets how strictly LispM Agent confines the commands and MCP servers its agents
run: None (the default), Low, Middle, High, or Custom rules edited in the panel.  See LispM
Agent's [[https://github.com/LispMachineLab/lispm-agent#the-sandbox][sandbox]].

#+begin_src emacs-lisp
(setq lispm-sandbox-level 'middle
      lispm-sandbox-allowed-domains '("api.example.com" "*.example.org"))
#+end_src

** Startup

The Startup panel opens LispM at login (a launch agent on macOS, an XDG autostart entry on
GNU/Linux) and opens startup items once the desktop shows: applications, documents, folders,
Emacs commands, and programs run in the background while LispM runs, their output in
=*Startup: NAME*=.

#+begin_src emacs-lisp
(lispm-desktop-open-at-login t)
(setq lispm-desktop-startup-items
      '((:program "ollama serve")
        (:app browser)
        (:file "~/notes/todo.org")
        (:program "npm run dev" :name "Site" :directory "~/site/")))
#+end_src

** Background work

LispM Kernel ([[https://github.com/LispMachineLab/lispm-kernel][lispm-kernel]]), a runtime for work Emacs should not wait on, is on by default.
It is a Common Lisp program, SBCL's runtime and the kernel's core in one executable, that Emacs
runs as a process, the two talking in S-expressions.  It reads the agents' sessions for the
sidebar on threads of its own, and Emacs takes them in on the desktop's frame clock; the sidebar
shows the sessions it has while it reads them anew.  It also makes the downloads package.el makes
in the background, as the App Store's refresh of the package archives, with curl, where url.el
would negotiate TLS on Emacs's thread; package.el checks and keeps what it gets as always.

Use LispM Kernel in Control Panels › Kernel turns it off and on, and the panel says how it stands;
so does:

#+begin_src emacs-lisp
(setopt lispm-desktop-kernel nil)               ; off at once, and at every start
#+end_src

Either takes effect at once, as does toggling it in Custom; nothing needs restarting.  Turned on
there, what the kernel lacks the Installer gets, showing how far it is; on by default, it gets it
quietly.  A kernel that exits is started again by itself: at once when it ran a while, else after
a pause that grows each time.

Its Lisp comes from =../lispm-kernel= beside this checkout, else package-vc installs its latest
release.  It gets its program itself, in the background: downloaded as built for this computer
by its =kernel program= workflow, and kept only when its SHA-256 is the one pinned in the kernel's
repository, beside its Lisp; nothing is built unless ~lispm-kernel-program-source~ is ~build~,
when SBCL builds it.  Until the program is there, and where it cannot be, the sidebar reads
sessions as it does without the kernel, url.el downloads for package.el, and the Kernel panel
says why.

** Updating

The Software Update panel keeps the checkouts in =~/.lispm= at their latest releases, and so a
LispM project the desktop installed as a package with package-vc, checking daily or weekly.
Updates install as LispM quits, never while it runs (Restart to Update installs at once): packages
are built again first, and the checkouts wait while one fails, since a desktop release may need an
agent release.  A checkout with changes of its own is left alone.  A project too old for the
desktop, as lispm-agent before 0.4.0, is brought up to date as LispM starts.  The App Store
updates its applications, by itself once LispM is idle if you allow it.
=M-x lispm-desktop-update-now= checks from anywhere.

* Mac OS and X

One configuration runs in the Mac build (NS) and in an X build, detecting the display and
Emacs's features at each start.  X frames go without Emacs's own menu bar, which the λ menu
replaces.  Windows out on the screen, the pointer watch and Chrome extensions are Mac only; the
browser needs xwidgets (WebKitGTK on X).

On an X display with no window manager, Emacs becomes it with [[https://github.com/emacs-exwm/exwm][EXWM]], installed when first
needed; ~(setq lispm-desktop-window-manager nil)~ turns this off.  On GNU/Linux, end =~/.xinitrc=
with =exec emacs=.

** X on macOS

Build a second Emacs against Homebrew's X libraries (=libx11=, =cairo=, =harfbuzz=, =librsvg=),
not XQuartz's: two libX11s in one process do not mix.

#+begin_src sh
./configure --prefix=$HOME/.local/emacs-x11 --without-ns --with-x \
  --x-includes=/opt/homebrew/include --x-libraries=/opt/homebrew/lib \
  --with-x-toolkit=no --with-cairo --with-harfbuzz --with-rsvg \
  --with-xpm=ifavailable --without-gsettings --without-native-compilation
make && make install
#+end_src

XQuartz's rootless mode has its own window manager.  To let Emacs manage windows, give it a
display of its own with Xephyr, which comes with [[https://www.xquartz.org][XQuartz]]:

#+begin_src sh
export DISPLAY=$(launchctl getenv DISPLAY)                # XQuartz's display, where a shell lacks it
/opt/X11/bin/Xephyr :2 -screen 1440x900 -resizeable       # in one terminal
DISPLAY=:2 ~/.local/emacs-x11/bin/emacs                   # in another
#+end_src

Clicking into Xephyr grabs the keyboard and mouse; Control-Shift releases them.  Both builds
share one configuration and its state files; the one that quits last keeps its own.

* In a terminal

=emacs -nw= runs the same configuration on a text terminal, over SSH too, and draws the chrome
in text: the menu bar, title bars in the manner of Turbo Vision, the desktop's icons down its
right edge, the Finder, Control Panels and the App Store.  Menus and alerts pop up as text with
Emacs 31, in the minibuffer before.  Agents and shells run in the same terminal module.  The
mouse works where the terminal reports it (=lispm-desktop-tty-mouse=; hold Shift to select text
the terminal's way), and Escape is typed twice in menus, as in Emacs's own.  Colours are exact
with =COLORTERM=truecolor=, the nearest of 256 otherwise.  The browser, the guide, the Control
Strip and the pointer watch need a graphical display.

* Writing an application

An application of the App Store is an Emacs package and one item of a catalog; it becomes the
desktop's in one way, the App Store's, at its install and at every start.

1. *The package* opens it with an autoloaded command showing its buffer, which the App Store runs in
   the application's window.  Only an application running windows of its own, as [[https://github.com/LispMachineLab/lispm-stickies][Stickies]] does,
   gives a ~:feature~ instead: a library that, loaded, says what it does with
   ~(lispm-desktop-define-app 'ID :activate ... :menus ... :running ...)~, ID being its catalog item's,
   and undoes its hooks in ~FEATURE-unload-function~.
2. *Its interface* is worked out from its mode; say the rest (buttons, status, pages) with
   ~lispm-desktop-app-ui-define~ inside ~(with-eval-after-load 'lispm-desktop-app-ui ...)~, so the package
   still runs in any Emacs.
3. *Its catalog item* in [[https://github.com/LispMachineLab/lispm-store][lispm-store]] is the only place saying what it is called, its subtitle, icon,
   category, description and needs; the App Store takes them from there, never from the package.
   It gives its whole listing, or the App Store does not list it: its banner, its introduction in
   Markdown (=lisp/lispm-desktop-markdown.el= reads it), its author and its licence.
4. *The checks*: =lisp/lispm-desktop-catalog.el= is the catalog's format, the one the App Store reads
   with and lispm-store's =make check= loads; =M-x lispm-desktop-store-check-catalog= lists what is
   wrong with a catalog of your own.  An error keeps an item out of the App Store, a warning fails the
   check.
5. *A pull request* to lispm-store adds the item, pinned to a reviewed commit (see its README).

* Development

=make test= runs the ERT tests, among them that every catalog of =i18n/= translates every message
the code gives (=make i18n= lists what each lacks), and =make compile= checks for byte-compiler
warnings; both need
LispM Browser, beside this checkout or named by =LISPM_BROWSER= (its =lisp/=).

The terminal module is downloaded, never built, unless you ask for it:

#+begin_src emacs-lisp
(setopt lispm-desktop-term-module-source 'build)   ; build it with cargo, at every change of its sources
#+end_src

=make native= builds it and =make native-test= runs its tests.  The =terminal module= workflow
publishes prebuilt modules as the releases =term-module-VERSION=, VERSION a digest of
=native/lispm-desktop-term='s sources.  LispM keeps a download only when its SHA-256 is the one
=lisp/lispm-desktop-term-sums.eld= pins: the pins travel in this repository's signed history, not
beside the binaries, so a library changed on a release is refused whatever its =SHA256SUMS= says.
After the sources change and the workflow has published their module, =make pin= writes the
pins (=scripts/pin-term-module.py= downloads and checks each library); a release commits them,
at the latest in its "Version X.Y.Z" pull request.  Until then main's sources are not pinned,
the module last downloaded keeps working, and only ~build~ gets one for them.
