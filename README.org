#+title: LispM Desktop

#+HTML: <p align="center"><a href="https://github.com/LispMachineLab/lispm-desktop/actions/workflows/test.yml"><img src="https://github.com/LispMachineLab/lispm-desktop/actions/workflows/test.yml/badge.svg" alt="test" /></a></p>

LispM's Emacs distribution: Emacs set up as a workspace for coding agents, ready from the first
start.  [[https://github.com/LispMachineLab/lispm-agent][LispM Agent]] runs agents inside Emacs;
LispM Desktop gives them a place to work, and puts Claude Code and Codex beside them when you have
those installed, and other agents, as Hermes, once its App Store has added them.  Its browser is
[[https://github.com/LispMachineLab/lispm-browser][LispM Browser]], drawn as Netscape
Communicator's window was.  In code, the prefix is ~lispm-desktop-~.

* The LispM projects

LispM is four projects, each a repository of its own under
[[https://github.com/LispMachineLab][LispMachineLab]]:

| [[https://github.com/LispMachineLab/lispm-agent][lispm-agent]]     | LispM Agent: AI agents that run inside Emacs, their conversations org documents, their tools Elisp |
| *lispm-desktop*   | LispM Desktop, this repository: Emacs laid out as Mac OS 9's desktop, a workspace for agents, ready from the first start |
| [[https://github.com/LispMachineLab/lispm-browser][lispm-browser]]   | LispM Browser: a WebKit browser in Emacs, with tabs, keyboard hints and Chrome extensions |
| [[https://github.com/LispMachineLab/lispm-store][lispm-store]]     | LispM Store: the catalog of applications and extensions LispM Desktop's App Store installs |

The agents and the browser each stand on their own; LispM Desktop runs both, the agents in its
sidebar and the browser as one of its applications, and installs them at its first start (see
[[*Installation][Installation]]).

* What you get

The frame is laid out as Mac OS 9 laid out its desktop, in the forms of a /look/: Mac OS 9's
Platinum appearance by default, or Windows 3.2's (navy captions, the control-menu box, sizing
borders, white menus), or OS/2 2.0's Workplace Shell (teal title bars over pale yellow borders,
the window's own icon as its system menu, pale grey menus).  Control Panels' Appearance switches
looks, and each brings its own colours.  Four colour themes come with it, asked for at the first
start and switched from the λ menu: Dracula; Platinum, Mac OS 9's own greys with black on white
and the Lavender accent; Windows 3.2's Windows Default scheme; and OS/2 2.0's.  Any theme draws
any look.

- *A desktop*, where Emacs starts, in the theme's colours tinted with its accent (Mac OS 8's
  blue-violet under Platinum), or a colour and a picture of your own (see [[*Your own
  settings][Your own settings]]).  Its icons stand down the right edge as Mac OS 9's did: the
  home disk and the applications, Emacs (with Emacs's own icon), the browser, the Applications
  folder (the App Store and what it installed), the App Store and the Control Panels folder, at the top,
  the Trash in the bottom corner, bulging once something is in it.  Click one to select it,
  double-click it (or press Return) to open it; C-n, C-p, C-f and C-b select from the keyboard
  and C-M-n, C-M-p, C-M-f and C-M-b move the icon selected a cell.  Drag one anywhere: a
  translucent copy of the icon and its name follows the mouse pixel by pixel, over other icons
  and windows alike, while the icon itself stays where it was, drawn selected, as Mac OS 9's
  Drag Manager did.  Let go, it lands on the grid the column lies on, in the free cell nearest
  (Escape gives up), and stays there at the next start too, kept by the edges nearest it so that it follows them as the
  desktop changes size.  Arrange Icons, in the desktop's right-click menu and its View menu,
  puts every icon back where it stood at first.  A desktop picture is drawn from a copy scaled to the desktop, made once by the
  system's =sips= (or ImageMagick), so clicks and drags stay quick.  Floating windows (the Finder's, the floating
  editor) stay whole on the desktop, which on macOS does not clip them: dragged past its edge
  they come back onto it, and when Emacs's frame changes size, as going full screen and back
  does, each returns to the place it was given, shrunk only while it does not fit.
- *A guide*, as Apple Guide showed Mac OS around: the first time LispM starts, a small window
  floating over the desktop goes through it a step at a time (the λ menu, the application in
  front, the desktop's icons, Emacs, the browser, the App Store, the Control Strip, windows and
  Emacs's own keys) while a red loop drawn as if by hand, a coach mark, circles each part it
  speaks of.  Each step shows its keys as key caps, and Show Me does what it shows: it opens
  the menu, Home, Emacs, the browser or the App Store, Emacs and the browser in windows over
  the desktop so the guide stays in sight, and puts them back as the guide goes on.  The first
  time, the guide plays by itself: each step does its Show Me a moment after it comes, and a
  menu it opened closes again.  =n= or Return goes on, =p= or DEL back, =s= shows, =q= puts it
  away and Skip leaves it.  It is an application built in, its window opening in the middle of
  the desktop: the Applications folder, the λ menu's Applications, the desktop's Help menu and
  =C-c ?= bring it back on the step it was left on, =C-u C-c ?= from the start, and its Go menu
  lists every step.
- *A Finder window*, opened by the home disk: a folder's items as large icons, floating over
  the desktop, the items and the room left counted in a header under its title bar, as Mac OS
  9's was, opened by a button reading the enclosing folder's name that goes up to it;
  Command-click its title, or type =C-c u=, for the folder's path.  A folder opens in the window, a file in the
  editor, which comes forward.  The arrows select, Return opens, Command-Up, Command-[ and
  Command-] go up, back and forward, Command-Delete moves the selected item to the Trash (the
  system's own, from where it can be put back), typing a name's first letters selects it, and
  a right click offers Open, New Folder, Rename, Move to Trash and Copy Path.  It belongs to the desktop: it shows
  with it, and with the floating editor and browser, and steps aside for the full-screen editor
  and browser.
- *Applications*, one in front at a time, as on Mac OS 9: the desktop, Emacs the editor, the
  browser, and those the App Store installs.  The one in front fills the menu bar with its menus; the Application menu at the
  right end names it and lists the others.  Files, folders, terminals and agents opened while the
  desktop or the browser is in front open in the editor, which comes forward.
- *A menu bar* along the top: LispM's rainbow λ at its left end, as Mac OS 9 had its rainbow
  Apple, opening the λ menu (new agents, sessions, shells, the browser, Control Panels), then the
  menus of the application in front: the desktop's File, View, Go and Special (Restart, Shut
  Down), the editor's File, Edit, View, Project and Window, the browser's File, View, Go,
  Bookmarks and Window.  At its right end, as Mac OS 9 held its clock there alone, Emacs's own
  time, with a menu of the date, the calendar and the world clock, then the Application menu.
- *The editor*, an application of its own: a title strip across its top, the editor's title bar
  over a row of tabs choosing the sidebar's view (Files, Agents, Shells), then the sidebar and
  the windows.  Its workspaces, one per project, drop from its Project menu as a panel of
  thumbnails, each drawn from the workspace's windows and their text in its colours; C-Tab
  and C-Shift-Tab step through them, Command-` brings the panel up.  It runs full screen,
  under the menu bar, or floating in a window over the desktop, moved by its title bar, resized
  from its grow box and rolled up by its collapse box; its zoom box moves it between the two,
  workspaces and all.  Its close box puts it away, leaving the desktop; it opens again as it was.
  A workspace with nothing open shows Emacs's own startup screen, its big logo over the links
  to begin with.
- *A buffer manager*, from the editor's Window menu: every open buffer with what it costs, as
  Mac OS 9's About This Computer barred each application's memory: its kind and the size of its
  text, and for one running a process (a terminal, an agent's CLI) the CPU and memory of that
  process and every process under it.  It refreshes itself while shown; Return shows a buffer,
  k closes it.
- *A title bar on every window*: a close box, the title between pinstripes, a zoom box and a
  collapse box.  Only the active window shows stripes and boxes, and a box is pressed, not
  clicked: it sinks while held and acts when let go over it.  The close box puts the window's
  buffer away (the last one leaves the desktop's colour showing through), the zoom box gives the
  window the whole main area and back, and the collapse box rolls it up to its title bar.
  Double-click a title bar to roll the window up (or zoom one alone in its column); drag it onto
  another window to swap the two (sessions only with sessions); Command-click it for the
  workspace's buffers.
- *Scroll bars*: Mac OS 9's, down each window's right edge: arrow boxes at both ends, a recessed
  track and a thumb in the accent colour with grip ridges.  Arrows and track repeat while held,
  the thumb drags.  An inactive window shows its empty track; sessions scroll their own way.
- *Window frames*: neighbouring windows meet as Mac OS 9's windows were framed, a dark outline
  on each edge and platinum between.
- *Floating windows* (the Finder's, the editor's, the browser's, a control panel's) are framed
  as Mac OS 9's were, an outline, a lit band and a drop shadow about them, and each is one
  window with its frame: the frame drawing it carries the window, so the two move, come in
  front, show and hide together.  Press a window's title bar or its frame and a dotted outline
  of it follows the mouse, the window staying where it is; let go, it moves there once, as
  Mac OS 9's DragWindow moved it.  The grow box drags the outline at the window's new size, with
  the lines of its title bar, its content and its grow box within, and the window takes that
  size once, at the end.  Escape or C-g gives a move or a resize up.
- *A bottom edge on every window*: placards for the buffer, its position, its diagnostics, its
  branch and its mode, and the grow box in the active window's corner.
- *Finder's icons*: folders (badged when they hold a git repository), a hard disk, documents by
  kind (text, code, Lisp, Markdown, Org, picture), a compact Macintosh for terminals, a robot for
  the agents and LispM's diamond for its records, in the sidebar, the title bars, the Application
  menu and the project tree.
- *A sidebar laid out as a Finder list*: a header holding the view's bevel buttons, column
  headings, disclosure triangles, one row per item with its date or place in the right-hand
  column, shaded down its length as the sorted column was, the selected row in the highlight
  colour, and a count of the items at the bottom.  The agents view lists every agent session,
  running or recorded, grouped by project: LispM's, those of Claude Code and Codex, and those of
  the agents the App Store added, as Hermes.  An agent run as a CLI takes part only while its
  program is on ~PATH~: without it, no button, menu item or key offers it and none of its sessions
  are listed.  Click one to resume it where it ran.
- *Control Panels*, as Mac OS 9's: the desktop's Control Panels folder opens a Finder window
  holding a panel each, and the λ menu's Control Panels lists them too.  A panel opens in a
  window floating over the desktop, titled with its name, its tabs choosing among the panels as
  the Appearance control panel's did, each group of settings framed in a group box.  Appearance chooses the look (Mac OS 9, Windows 3.2,
  OS/2 2.0) and the colour theme (Dracula, Platinum, Windows 3.2, OS/2 2.0, or any other
  installed); Desktop the desktop's colour, its picture and how the picture covers
  it (fill, fit, center, tile), and arranges its icons; Keyboard Vim or Emacs keys; Language the
  language LispM speaks (see [[*Languages][Languages]]); Internet the
  browser's home page and search address, its history and its bookmarks; Network the proxy every
  connection goes through (see [[*A proxy][A proxy]]); Sandbox how strictly the commands agents
  run are confined (see [[*The sandbox][The sandbox]]); Startup whether LispM opens at login and
  what it opens once started (see [[*Startup][Startup]]); Software Update keeps LispM up to date (see
  [[*Updating][Updating]]).  Each choice takes effect at once where it can
  and is kept for the next start.
- *The App Store*, laid out as the Mac App Store in Mac OS 9's forms, installs what LispM runs
  beyond what it ships with: applications, Emacs packages each running in a window of its own on
  the desktop (Elfeed, EMMS, ERC, Slack and Telega to chat, Emacs's own Calculator and its
  games); and extensions, packages
  adding to the editor, as Hermes, an agent beside Claude Code and Codex.  It lists them from
  catalogs, git repositories holding a =catalog.eld=,
  [[https://github.com/LispMachineLab/lispm-store][lispm-store]] by default
  (~lispm-desktop-store-catalogs~): the categories down the left (All, News, Music,
  Social, Productivity, Utilities, Games, Extensions, Updates), the chosen one's items as icons in a
  grid, each with its button, Get, Open or Update; under the grid Install from URL… and Remove,
  and the selected item's information below.  An extension whose program is not on ~PATH~ is
  greyed out, its information saying how to install the program.  Nothing is installed unasked:
  where a package comes from and the commit it is pinned to shows under the window while an
  alert asks, and an update shows what changes.  Packages are installed and updated in an Emacs
  of their own, in the background, one after another, so the desktop goes on meanwhile: the
  item's button gives way to Mac OS 9's progress bar and its subtitle to what is being done
  (waiting, downloading, building); its information says how far, and Stop under the grid stops
  it, what it installed undone.  One that fails says why, offers Try Again, and Show Log shows
  what its Emacs said.  Install from URL… takes a git URL: a repository with a catalog becomes
  one more catalog, any other Emacs package an application.  The λ menu and the desktop's App
  Store icon open it; the λ menu lists the applications installed, and so does the desktop's
  Applications folder.  The keyboard does all of it: =C-f=, =C-b=, =C-n=, =C-p= from icon to
  icon, =M-n=, =M-p= from category to category, =RET= or =SPC= presses the selected item's button,
  =/= searches, =i= shows its information, =u= updates, =D= removes, =.= stops an install, =l=
  shows the log of one that failed, =g= checks the catalogs, =+= installs from a URL.
- *The applications* the App Store installs, Emacs packages written for Emacs's own windows, get
  the desktop's interface in theirs: their name and icon in the title bar, not a buffer's name;
  a strip of push buttons for their main commands (New Game, Pause, Update); what they report
  on placards along the window's bottom (the score, the date, what is playing); their own
  menus in the menu bar, or one listing their commands with their keys, and a Help menu whose
  /Keys/ window shows every key; their questions in alerts; no line numbers; and a game's
  window as large as its board.  All of it is found out from the package itself, its mode's
  keymap, menus and variables, so a package nobody described gets it too, the arrows it binds
  also on =C-f=, =C-b=, =C-n=, =C-p=.  What cannot be found out is described with
  ~lispm-desktop-app-ui-define~ (=lisp/lispm-desktop-app-ui.el=): Emacs's games have their boards
  drawn in Platinum's forms and played with the mouse as with their keys, Tetris, Snake and Pong
  their cells as Platinum tiles, the Calculator a keypad, the Calendar its months drawn as
  calendars, Elfeed and EMMS a page saying how to begin while they have nothing to show.  EMMS
  plays with macOS's own afplay and reads tags through Spotlight where mpv and exiftool are not
  installed, and imports the Music app's library and playlists, read-only, through Apple's
  iTunesLibrary, by a small application built the first time (=native/lispm-music-library=).
  What an app uses beyond Emacs, programs, libraries and applications, its catalog declares
  as its needs (=lisp/lispm-desktop-needs.el=): Get installs those missing with the app, the
  alert asking for both, in the *Installer*, a window of its own, one install at a time with
  Homebrew (offered first where it is not installed, its installer asking for the password in
  a terminal), saying what fails and trying it again; the app's window offers what is missing
  as it opens, its Help menu too, and a command needing a program offers it before it runs.  The
  applications to chat with (=lisp/lispm-desktop-app-chat.el=) open on the list of their
  conversations, as chat applications do, each network or workspace over its channels and
  people, those with messages unread in bold with their count, in red where they name you; a
  conversation opens in the same window, Back going back.  ERC connects again at its next start
  to the networks it was on and joins their channels; Slack signs in with the token and cookie
  of Slack's web app, kept with auth-source; Telega's window says what it lacks, TDLib or a C
  compiler, installs it, and builds telega-server once it is there.  A package can describe
  itself the same way.  =M-x lispm-desktop-app-ui-audit= opens every
  application installed in turn and lists what of this it finds missing.
- *A watch on the pointer* while LispM works, as Mac OS 9 showed one: its wristwatch, copied
  off its screen pixel by pixel, the minute hand going round.  It shows once Emacs has been at
  work longer than Emacs's own ~hourglass-delay~ (a second), on a long command or a program it
  waits for (~display-hourglass~ set to nil turns that off), and while something loads for the
  window in front: the App Store checking its catalogs or looking at a URL, and installing or
  updating in Emacs itself rather than in the background (where its progress bars show it),
  Control Panels while Software Update checks.  It shows over LispM's windows only, and a loading's only while
  its window is in front, as Mac OS 9's watch was the application in front's.  Code says it
  loads with ~lispm-desktop-with-loading~ around work it does there and then,
  ~lispm-desktop-loading-process~ for a process it waits for, or ~lispm-desktop-loading-start~ and
  ~lispm-desktop-loading-stop~ (=lisp/lispm-desktop-loading.el=), for a frame, a window, a buffer,
  or whatever is in front.  Emacs's Mac build has neither pointers of images nor a busy one, so
  the terminals' module draws the watch (=native/lispm-desktop-term/src/cursor.rs=), from the
  time it is built or downloaded.
- *The Control Strip*, as Mac OS 9's, floating over the windows along the desktop's edge, in its
  bottom-left corner at first: a collapse box, scroll arrows, a module each for Appearance, Desktop, Keyboard and
  Internet, and Emacs's own battery, load average and mail flag, then a tab.  Pressing a module
  pops its menu up in the small system font: its panel's quick choices (the theme, the desktop's
  colour and picture, Vim or Emacs keys, the home page) and the panel itself, or the battery's
  charge, the load averages and the processes, reading, composing and checking mail.  The
  collapse box leaves the tab, the tab brings the strip back, and dragging the tab sets how many
  modules show.  Dragging the tab with Command held moves the strip, as Mac OS 9's Option-drag
  did (lispm-desktop leaves Option to macOS for typing): an outline follows the mouse up and down
  the edge, and over to the right edge past the desktop's middle, where the strip turns round,
  its tab to the left; the strip moves once the mouse is let go.  =C-c B= hides it and shows it
  again, as the Control Strip control panel's hot key did.  All of it is kept for the next start.
- *A browser*, when Emacs is built with xwidgets: [[https://github.com/LispMachineLab/lispm-browser][LispM Browser]], an application of its own, opened from the
  desktop or the λ menu and brought forward from the Application menu.  Its window is laid out
  as Netscape Communicator's was, in the theme's colours: the navigation toolbar (Back,
  Forward, Reload, Home, Search, History, Stop, and the Netscape N, its meteors falling while a
  page loads), the location toolbar (the Bookmarks button, the page's icon, the address, and
  the buttons of the extensions), the
  personal toolbar of bookmarks, a row of tabs, and a status bar with the padlock, the progress
  bar and "Document: Done".  It keeps a history of the pages visited (=lispm-browser-history-file=)
  and bookmarks, which are Emacs's own (=bookmark.el=), so =bookmark-jump= opens them too; both
  list in a pane at the window's left (History, Bookmarks › Edit Bookmarks), where a click
  opens a page, a middle click opens it in a new tab and a right click renames, deletes or
  forgets.  Like the editor it is full screen, in a workspace of its own (the floating editor
  steps aside), or floating over the desktop beside the other windows; its zoom box, or View ›
  Full Screen and Floating Window, moves it, and it opens again as it was.  Closing its last
  tab quits it, as File › Quit Browser does, and the desktop comes back.  Pages are used from
  the keyboard as Vimium uses them: =f= labels the links, buttons and fields in sight, and
  typing a label follows it; in a field, characters go in and Emacs's keys move and delete,
  Return submits, Tab goes on and Escape leaves.  Emacs on macOS cannot hand keys to a page,
  so they reach it through JavaScript.
- *Chrome extensions in the browser*, on macOS 15.4 and later: WebKit runs them itself, as Safari
  runs its own (WKWebExtension), in every page whose view carries its extension controller, and a
  dynamic module in Swift hands Emacs's page views that controller as they are made.  They are
  used as in Chrome, from the location toolbar: it ends with a small bevel button per extension
  pinned to it, the extension's own icon with its badge, and a click opens its popup under the
  button (pushed in while the popup is up) or tells the extension it was clicked; a right or
  Control click shows its menu (unpin, options, manage, remove).  After them the Extensions
  button, a puzzle piece, opens the menu of them all, also in the menu bar: each running
  extension, Pin to Toolbar with each one checked, the Chrome Web Store, Load Unpacked (as
  Chrome's developer mode does) and Manage Extensions, the browser's page of them at
  =lispm://extensions=, to turn each on and off, see what it may do, reload or remove it.  On an
  extension's page in the store, Add to LispM stands where the store's Add to Chrome did (that
  one is Chrome's alone): the extension is fetched, its signature checked and what it will be
  able to do asked first, and it comes pinned.  An extension not pinned shows on the toolbar
  while its popup is up.  From the keyboard, =M-e= presses one, its popup under its button.
  Their tabs are the browser's pages, their questions are asked in the minibuffer, and they
  live in =lispm-browser-extensions-directory=.  Most of
  the module is ported from [[https://github.com/driceroland/Search][Search]], a WebKit browser for
  macOS, with the script Search puts in every extension to fill in the Chrome APIs WebKit lacks
  (notifications, offscreen documents, a worker's WebSockets, user scripts, the side panel as a
  tab…) and to mend where WebKit behaves otherwise, so heavy extensions such as the Rabby wallet
  run: its worker, its page provider (=window.ethereum=), its popup.  A window an extension opens
  of its own, a wallet's approval of a transaction, is a Mac window whose page takes the keyboard.
  Bookmarks, history and downloads stay the browser's (an extension finds them empty), and no app
  on the Mac is spoken to (native messaging).  An Emacs started with
  =LISPM_BROWSER_WEBEXT_VERBOSE= set lists what extensions write to their consoles as errors and
  warnings with their errors, for finding out why one fails.
- *Windows out on the screen*, on macOS (see [[*Mac OS and X][Mac OS and X]]), as a virtual machine's in Parallels' Coherence or
  VMware's Unity: drop a floating window, the Finder's, the editor's, the browser's or a control
  panel's, mostly past the desktop's edge, and it goes out among the computer's own windows,
  where it was dropped; dropped back over the desktop, it goes in again.  Hide Desktop, at the
  top of the Application menu or =C-c h=, takes every window out, the full-screen editor and
  browser floated first, and puts the desktop in the Dock; Show Desktop, =C-c h= again or a
  click on its tile in the Dock brings it back, the windows over it going in and the
  applications full screen as they were.  A window out keeps its frame, its title bar and its
  boxes, and moves and grows by its outline as over the desktop; what it
  asks, and the messages it echoes, show in a small window over the top of the screen, titled
  with its name, since the desktop's own minibuffer is in the Dock with it.
- *Menus and alerts*: the λ menu, the Application menu, a title bar's buffer menu, every
  right-click menu (Emacs's context menu, the sidebar's, the project tree's) and every menu a
  package pops up drop as Mac OS 9's menus did, with check marks, separators, key equivalents
  and hierarchical submenus; closing a modified document asks to save it (Return saves, Escape
  cancels, Command-D doesn't save), closing a running session or deleting one asks first, and
  quitting asks so of each unsaved document and before stopping the programs still running,
  agents in terminals included, each in an alert with the caution, stop or note icon and the
  default button ringed; Tab and C-f, C-b move an outline among the buttons and Space presses
  the one outlined.
- *Details*: a thin insertion point (Evil's normal state keeps its block), and help over a
  control shown as Balloon Help.
- *A main area* that keeps agent chats and terminals on the left and everything else, files
  first, on the right, however a buffer is opened, and *a workspace per project*, owning that
  project's buffers.
- *Agents that see Emacs*: Claude Code connects over its IDE protocol, Codex (and Hermes, once
  installed) over MCP, and all of them can read the selection, the open and unsaved files, and
  Flymake's diagnostics.
- *Terminals that never stall Emacs*.  Emacs runs Lisp, process output and redisplay on one
  thread, so a terminal emulated in Lisp decodes everything its program writes on that thread,
  shown or not, and a few agents resuming long sessions at once froze Emacs.  lispm-desktop
  emulates each terminal on a thread of its own instead, in a dynamic module written in Rust
  (=native/lispm-desktop-term=, on [[https://github.com/alacritty/alacritty][Alacritty]]'s terminal), and
  wakes Emacs only for the terminals a window shows, to draw the lines that changed: Emacs's work
  follows the windows on screen, not the number of agents running or how much they write.
  Shells and agents run in it once it is built, which happens in the background at the first
  start where Rust's Cargo is installed, and again when an update changes its sources.  Without
  Rust, the start downloads the module this repository's workflow built from the same sources
  for the computer (macOS on Apple silicon or Intel, GNU/Linux on x86_64), from the release
  named by their digest, and checks it against the SHA-256 published with it
  (~lispm-desktop-term-download-enabled~ set to nil keeps it from downloading).  Until either
  is there, they run in Eat.  A program that takes the mouse, as Claude Code does, gets the
  clicks, drags and wheel; with Shift held they stay Emacs's, to select text.
- *Agents that say what they are doing*.  A program that reports its state with the [[https://superlogical.com/rex/docs/build/program-status][Program
  Status Protocol]] (OSC 7501) has it shown in its window's title bar and in the agents
  view: working, done, failed, or waiting for an approval, an answer or a sign-in.
  =C-c a n= goes to the next terminal waiting for you.
- *Completion everywhere* (Vertico, Orderless, Consult, Embark, Corfu), Magit, Eglot and
  tree-sitter modes.
- *Vim or Emacs keys*, chosen at the first start.  With vim keys, Evil edits program, text and
  configuration files, SPC is the leader key, and terminals, chats and the sidebar keep Emacs keys
  so the programs in them get every key.
- *X windows as buffers*, when Emacs runs on an X display that has no window manager: Emacs
  becomes it (see [[*Mac OS and X][Mac OS and X]]).

Title bars and menus are set in Charcoal when it is installed, else Chicago (ChicagoFLF, a free
revival whose author considers it public domain, works too) or Geneva; lists in Geneva.  macOS
still ships Geneva; the others are not distributed with lispm-desktop.

* Installation

** LispM.app, on macOS

LispM.app is GNU Emacs under LispM's name and icon, running LispM Desktop with the agents and
the browser: nothing needs to be known about Emacs to use it.  On macOS 11 or later, on Apple
silicon or Intel, open Terminal and paste:

#+begin_src sh
curl -fsSL https://lispm.ai/install.sh | sh
#+end_src

That runs [[file:install.sh][install.sh]].  It installs Apple's command line tools when they
are missing (git, and the compiler Emacs turns its packages into machine code with), checks out
this repository with lispm-agent and lispm-browser beside it in =~/.lispm=, downloads GNU Emacs
as [[https://github.com/jimeh/emacs-builds][jimeh/emacs-builds]] builds, signs and notarizes it,
checks its checksum and its signature, and makes LispM.app of it in =/Applications= (else
=~/Applications=): LispM's name, icon and bundle identifier, and as its executable a small
launcher ([[file:macos/launcher.c][macos/launcher.c]]) that starts the Emacs inside with the
checkout as its init directory.  It then installs the packages LispM Desktop uses, builds the
browser's Chrome extensions support with Swift, and LispM's terminals where Rust's Cargo is
installed (else it downloads them, built for the Mac and checked), and opens LispM, whose
first start asks only how you edit and which appearance you want.

LispM keeps itself up to date (see [[*Updating][Updating]]); running the line again updates it
too.  The checkout keeps what Emacs writes, the packages and your
settings (=personal.el=) among it; to uninstall, delete =/Applications/LispM.app= and =~/.lispm=
(where =skills/= holds the skills you wrote for LispM's agents, if any).

** In your own Emacs

Requires Emacs 30.1 or later (31 recommended) built with SVG images (librsvg, as macOS builds
and most distributions' are), git and curl, on macOS or GNU/Linux.

Try it without touching your configuration:

#+begin_src sh
git clone https://github.com/LispMachineLab/lispm-desktop ~/lispm-desktop
emacs --init-directory ~/lispm-desktop
#+end_src

or make it your configuration (move an existing =~/.emacs.d= and =~/.emacs= out of the way first):

#+begin_src sh
git clone https://github.com/LispMachineLab/lispm-desktop ~/lispm-desktop
ln -s ~/lispm-desktop ~/.emacs.d
emacs
#+end_src

=git clone --depth 1= skips the repository's history, its pictures and recordings of earlier
versions among it.

The first start asks whether you edit with vim or Emacs keys and which appearance you want, on
a page filling the window, as Mac OS Setup Assistant asked: a choice's letter, or Tab and
Return, or a click chooses it, DEL goes back and Escape decides later.  Then it installs the
icon font agents' marks are drawn with, and the packages (a few minutes, once), LispM Agent and
LispM Browser among them, and once LispM is up, the guide shows it around.  LispM Agent and
LispM Browser are each found where they already are: on ~load-path~, else in
a checkout beside the desktop's (=../lispm-agent=, =../lispm-browser=), else installed from its
repository with package-vc.  To work on all three, clone them side by side:

#+begin_src sh
git clone https://github.com/LispMachineLab/lispm-agent ~/lispm-agent
git clone https://github.com/LispMachineLab/lispm-browser ~/lispm-browser
#+end_src

Then give LispM Agent a model: with ~OPENAI_API_KEY~ or ~ANTHROPIC_API_KEY~ set in Emacs's environment
nothing more is needed; for any other server, local or hosted, see LispM Agent's
[[https://github.com/LispMachineLab/lispm-agent#backends][Backends]] and put the settings in your =personal.el=.

Optional, and picked up when present:

- [[https://github.com/anthropics/claude-code][Claude Code]] (~claude~) and Codex (~codex~) on ~PATH~;
  Hermes (~hermes~) too, once the App Store has added it;
- [[https://rustup.rs][Rust]] (~cargo~), to build the terminals' module (=make native= builds it by
  hand); without it, the module built for your computer is downloaded, see above;
- Swift (Xcode or its command line tools), on macOS 15.4 and later, to build LispM Browser's
  module that runs Chrome extensions, the first time one is added;
- the Maple Mono NF CN font, whose glyphs keep terminal columns aligned, CJK included
  (=brew install --cask font-maple-mono-nf-cn= on macOS);
- a spell checker (aspell, hunspell or ispell) for Flyspell;
- an Emacs built with xwidgets, for the embedded browser.

* Mac OS and X

The same configuration runs in the Mac OS build of Emacs (NS, as Emacs.app and emacs-plus are)
and in an X build.  Nothing is set per machine: each start looks at the display Emacs has and at
what it was built with.

- *The menu bar*: Mac OS draws Emacs's menu bar at the top of the screen.  On X it would be a
  second bar inside the frame, under the Platinum menu bar, so X frames go without; the λ menu
  and the application's menus have everything.
- *The default font*: Monaco, else Menlo, else DejaVu Sans Mono, at 12 points.  The Mac build
  falls back to Monaco and an X build to fontconfig's =monospace= (Andale Mono on a Mac);
  naming the family makes them alike.  A default face set with Customize is kept.
- *Windows out on the screen* go out on macOS only, for now.  On X, under a window manager or
  with Emacs as one, Hide Desktop is not in the Application menu, =C-c h= says why, and a window
  dropped past the desktop's edge is kept on it, as everywhere before.  On macOS a desktop full
  screen leaves full screen to go to the Dock, and takes it back when it shows again; while it
  is full screen, dropping a window moves none out.  =(setq lispm-desktop-coherence-drag-out nil)=
  keeps dropped windows on the desktop, Hide Desktop still taking them out.
- *Outlines and drag images*: on macOS a child frame is not clipped by its parent, so a
  window's outline passes the desktop's edge as the window is dragged out; X clips it at the
  edge.  No window system inverts what a frame shows, so the outline's dots are the theme's
  outline over the desktop's colour where Mac OS 9 inverted the screen.  A dragged icon's copy
  is translucent where frames can be (macOS, X with a compositing manager), opaque elsewhere.
- *The browser* needs an Emacs built with xwidgets (on X, with GTK and WebKitGTK); without, its
  icon and menu items are not shown.  Its pages run Chrome extensions in the Mac build only, on
  macOS 15.4 and later: WebKitGTK has no extension engine, so elsewhere there is no Extensions
  menu.
- *The watch on the pointer* is drawn in the Mac build.  Under X, Emacs shows its own busy
  pointer, as X's watch, and loadings leave the pointer as it is.
- *Tree-sitter modes* are used when Emacs is built with tree-sitter.
- *Modifier keys*: Command is Meta in the Mac build; an X build takes its modifiers from the X
  server's keyboard map.

** Emacs as the window manager

On an X display that no window manager runs on, Emacs becomes its window manager: [[https://github.com/emacs-exwm/exwm][EXWM]]
shows every X window, a terminal, a browser, any X program, as a buffer, which then goes into
windows and workspaces as any buffer does.  EXWM is installed the first time it is needed.

A display that has a window manager keeps it, a Linux desktop's or XQuartz's: Emacs looks for
the check window an EWMH window manager names on the root window, and one named by a window
manager that has quit does not count.  To never manage windows, put this in =personal.el=:

#+begin_src emacs-lisp
(setq lispm-desktop-window-manager nil)
#+end_src

On GNU/Linux, run Emacs as the X session itself, for instance with =exec emacs= at the end of
=~/.xinitrc=.

** X on macOS

A build of Emacs has one window system, Mac OS or X, never both.  To have X on a Mac, build a
second Emacs beside the Mac one and use [[https://www.xquartz.org][XQuartz]] (=brew install --cask xquartz=) as its X server:

#+begin_src sh
./configure --prefix=$HOME/.local/emacs-x11 --without-ns --with-x \
  --x-includes=/opt/homebrew/include --x-libraries=/opt/homebrew/lib \
  --with-x-toolkit=no --with-cairo --with-harfbuzz --with-rsvg \
  --with-xpm=ifavailable --without-gsettings --without-native-compilation
make && make install
#+end_src

Take every X library from Homebrew (=libx11=, =cairo=, =harfbuzz=, =librsvg=), not from
XQuartz's =/opt/X11=: Homebrew's cairo and librsvg bring Homebrew's libX11, and two libX11s in
one process do not mix.  Homebrew has no libXaw, hence no toolkit; lispm-desktop draws its own
menus.  librsvg is what the Platinum chrome's pictures need.

XQuartz normally runs rootless: each X window is a Mac window, and quartz-wm is the window
manager, so there the X Emacs is an ordinary window and EXWM stays off.  To let Emacs manage the
windows, give it a display of its own.  Xephyr, which comes with XQuartz, is an X server that
draws its whole screen inside one window of another; run it in one terminal:

#+begin_src sh
export DISPLAY=$(launchctl getenv DISPLAY)   # where a shell lacks XQuartz's display
/opt/X11/bin/Xephyr :2 -screen 1440x900 -resizeable
#+end_src

and the X Emacs on it from another:

#+begin_src sh
DISPLAY=:2 ~/.local/emacs-x11/bin/emacs
#+end_src

Clicking into Xephyr's window grabs the keyboard and the mouse; Control-Shift lets them go.
Closing that window ends the display and the Emacs on it, so quit Emacs first (=C-x C-c=).
Alternatively, XQuartz's full-screen mode (rootless off in its preferences) with a =~/.xinitrc=
that starts the X Emacs instead of quartz-wm gives Emacs the whole screen.

Two things to know when both builds run:

- They read the same configuration and write the same state (the minibuffer history, recent
  files, places in files); the one that quits last keeps its own.
- Points become pixels at the display's resolution.  Xephyr's screen above reports about 75
  dots per inch, so text there is about the Mac build's size; XQuartz's own display reports
  96, a third larger.  =Xft.dpi: 72= in =~/.Xresources=, which XQuartz loads when it starts,
  matches them on that display, for every X program.

* Your own settings

Put them in =personal.el= next to =init.el= (git ignores it); it is loaded after lispm-desktop is
set up, so it can change anything, and the appearance takes a new value at once:

#+begin_src emacs-lisp
;; The look: platinum (Mac OS 9), win3 (Windows 3.2) or os2 (OS/2 2.0's
;; Workplace Shell).
(setq lispm-desktop-look 'platinum)

;; The colour theme: dracula, platinum (Mac OS 9's greys), win3, os2, or any
;; theme you have installed; the menu bar, title bars and lists take their
;; colours from it.
(setq lispm-desktop-theme 'platinum)

;; The desktop: a colour of its own, rather than the theme's tinted with its
;; accent (any colour Emacs knows: "#6666AA", "dark slate blue", "gray40"), and
;; a picture over it (a PNG or a JPEG), placed as Mac OS 9's Desktop Pictures
;; were: fill (cropped to the desktop), fit, center or tile.
(setq lispm-desktop-color "#6666AA")
(setq lispm-desktop-picture "~/Pictures/desktop.jpg"
      lispm-desktop-picture-position 'fill)
#+end_src

The control panels set the theme, the desktop, the keys and the browser too, and keep them
for the next start, as dragging the desktop's icons keeps their places
(~lispm-desktop-icon-places~); so do =M-x lispm-desktop-set-theme= and =M-x lispm-desktop-choose-picture=.

An existing configuration can use lispm-desktop as a library instead:

#+begin_src emacs-lisp
(add-to-list 'load-path "~/lispm-desktop/lisp")
(setq lispm-desktop-editing-style 'vim)           ; or 'emacs; nil asks
(require 'lispm-desktop)
(lispm-desktop-setup)
;; ... your settings
#+end_src

LispM Agent and LispM Browser are found as at the first start: on ~load-path~, else beside the
desktop's checkout, else installed with package-vc.

* Languages

LispM speaks English (US), English (UK), German, French, Japanese, and Chinese, Simplified and
Traditional.  By default it speaks the computer's language: the first of macOS's preferred
languages it knows, or, elsewhere, of =LANGUAGE=, =LC_ALL=, =LC_MESSAGES= and =LANG=; else
American English.  The first start asks for it before the other questions, and the next pages
speak it; the Language control panel changes it later, at once: menus, windows, panels, alerts
and the Guide.  Documents, web pages, and what programs and agents say keep their own language.
In your personal.el:

#+begin_src emacs-lisp
(setopt lispm-desktop-language 'ja)   ; or en-US, en-GB, de, fr, zh-Hans, zh-Hant; nil: the computer's
#+end_src

The code writes its words in English, each through ~lispm-desktop-tr~ (or ~-tr-n~ for a count,
~-tr-in~ for a meaning in a context, ~-tr-noop~ for words kept in a list until shown), and the
catalogs of =i18n/= translate them, one per language.  The tests check that every catalog but
the English ones translates every message, keeping its =%s= arguments, and holds none the code
no longer gives; =make i18n= lists what each lacks.  The English catalogs hold only what their
spelling changes: the code spells as Britain does, its words as Mac OS 9 had them.

* A proxy

The Network control panel sends every connection LispM makes through one proxy, HTTP or SOCKS5,
at the address given as =host:port=; by default there is none, and Emacs connects as its
environment says.  It takes effect at once: Emacs's own requests (url.el's, which package.el
and EWW use: an HTTP proxy tunnels HTTPS with CONNECT, a SOCKS5 one carries TLS and looks the
names up), the programs Emacs starts (git, curl, the agents, the terminals' shells, through
=http_proxy=, =https_proxy=, =all_proxy= and =no_proxy=) and the browser's pages (handed to
WebKit by LispM Browser).  This computer's own addresses, where LispM's servers and the models
served locally listen, never go through it, nor do the hosts listed under Direct Connections.
personal.el can set it too:

#+begin_src emacs-lisp
(setq lispm-desktop-proxy-type 'socks5            ; or 'http; nil for none
      lispm-desktop-proxy-server "127.0.0.1:7890"
      lispm-desktop-proxy-exceptions '("intranet.example"))
#+end_src

* The sandbox

The Sandbox control panel chooses how strictly LispM Agent confines the shell commands and MCP
servers its agents start, as =/sandbox= in a chat does.  None, the default, leaves them free to do
whatever you can; Low, Middle and High run them in srt, Anthropic's sandbox runtime, each
stricter than the one before, as the panel says under each.  The choice takes effect at once and
is kept for later starts: running commands take its network rules at once, its file rules when
they start again.  A level chosen elsewhere, with =/sandbox= or =M-x lispm-sandbox-set-level=,
shows in the panel as it is made.

The first level other than None installs srt with npm (Node.js 22.12 or later).  The panel says
while it is being installed, or why it cannot be, with Try Again; until srt runs, commands that
should be confined fail rather than run outside it.  Allowed Domains are the domains commands may
reach at Low, besides package registries and code hosts, and at Middle, alone: =example.com=,
=*.example.com= for its subdomains, or =example.com:443=.  The panel shows with LispM Agent 0.3.0
or later.

With LispM Agent 0.4.0 there is a fifth level, Custom, of rules of your own; while it is chosen,
the panel shows them under Custom Rules.  Start from Low, Middle or High copies a level's rules
(asking first when that replaces rules you set); each list, what commands may not read, may read
after all, may write, may not write, the domains they may reach and those refused, and the Unix
sockets they may connect to, has a Change… button; check boxes let them serve on local ports, use
pseudo-terminals and, on macOS, send Apple Events, which opens applications outside the sandbox.
Customize… edits the same rules in Customize.  Until you change one, Custom has Middle's rules.
personal.el can set all of it:

#+begin_src emacs-lisp
(setq lispm-sandbox-level 'middle                 ; none, low, middle, high or custom
      lispm-sandbox-allowed-domains '("api.example.com" "*.example.org")
      lispm-sandbox-custom '(:deny-read ("~/.ssh") :allow-write (".")
                             :allowed-domains ("github.com") :local-binding t))
#+end_src

* Startup

The Startup control panel chooses what starts with LispM.

Open LispM when you log in has the computer open LispM at login, the same application and
configuration that runs now.  On macOS it is a launch agent,
=~/Library/LaunchAgents/org.lispmachinelab.lispm.login.plist=, running =open -a= on LispM.app
(or the Emacs.app LispM runs in), which System Settings lists in its Login Items; on GNU/Linux an
autostart entry, =~/.config/autostart/lispm.desktop=, which GNOME, KDE and the other desktops
read.  The file is the setting: LispM writes it when the box is checked and deletes it when it is
unchecked.

Startup Items, as the Startup Items folder of Mac OS 9's System Folder, are opened once LispM has
started and the desktop shows, in their order: applications (the desktop's and the App Store's),
documents (in the editor) and folders (in the Finder window), programs and Emacs commands.  A
program is a shell command run in the background while LispM runs, as a service, in a directory
of its choice; its output goes to a buffer of its own (=*Startup: NAME*=), quitting LispM stops
it without asking, and the panel tells whether it runs.  Each item has a check box that turns it
off without taking it out; Add…, Remove… and Open… do the rest.  personal.el can set both:

#+begin_src emacs-lisp
(lispm-desktop-open-at-login t)
(setq lispm-desktop-startup-items
      '((:program "ollama serve")                    ; :name, :directory optional
        (:app browser)
        (:file "~/notes/todo.org")
        (:command lispm-desktop-shell-new)
        (:program "npm run dev" :name "Site" :directory "~/site/" :disabled t)))
#+end_src

* Updating

The Software Update control panel, as Mac OS 9's, keeps the checkouts LispM runs from up to
date with the branch each follows: the desktop's, and LispM Agent's and LispM Browser's where
they are checked out beside it (=~/.lispm= holds all three).  Update Now checks at once; by
itself it checks every day, or every week, in the background.  An update is installed as LispM
quits, never while it runs, so that old code and new never mix: Restart to Update installs it
at once, else the next quit does; with Ask me before installing updates checked, it waits for
Restart to Update.  A checkout with changes or commits of its own, or on no branch, is left as
it is.  An update to LispM.app itself (=install.sh=, =macos/=) is made by =install.sh=, run
after LispM quits, which opens LispM again when it is done.  The log (Show Log) lists what was
installed, and =M-x lispm-desktop-update-now= checks from anywhere.

The App Store's applications and extensions are updated by the App Store, which looks for
updates whenever Software Update checks, and as its window opens: a package its catalog pins
to another commit than installed, or one from the package archives that are newer there.  With
Update applications automatically checked, in the same panel, they install by themselves once
LispM has been idle a minute, without asking, an application once its window is closed;
unchecked, they wait in the App Store's Updates, and the panel names them.

Where package-vc installed LispM Agent and LispM Browser, =M-x package-vc-upgrade-all= updates
them, and =M-x package-upgrade-all= the other packages.  When the update changed the terminals'
module, the next start rebuilds it in the background (downloads it, without Rust), terminals
running in Eat until it is ready.

* Tests

=make test= runs the ERT tests in batch, in the code's own English; =make i18n= lists the messages
each catalog of =i18n/= lacks; =make compile= byte-compiles every module against the
installed packages, to check for warnings, and leaves no =.elc= files behind.  Both need
LispM Browser: a checkout beside this one, or another named by =LISPM_BROWSER= (its =lisp/=).
=make native-test= runs the terminals' module's own tests, which need Cargo but no Emacs.

The =terminal module= workflow builds that module for macOS on Apple silicon and on Intel and
for GNU/Linux on x86_64, and from =main= publishes each version of its sources once, as the
release =term-module-VERSION= LispM downloads where Cargo is missing (VERSION is
~lispm-desktop-term-source-version~ of the sources).
